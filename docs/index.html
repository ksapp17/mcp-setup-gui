MCP Setup turns any HTTP API into tools Claude can use, and installs them in Claude Desktop, Claude Code or claude.ai. Your API keys stay in your operating system's keychain.

What it does

Import an API from its OpenAPI spec
Paste a spec URL and pick the operations you want. Read-only ones are preselected; deletes are marked so Claude asks first.
Install without touching JSON
Shows the exact change to Claude's config file, backs it up, writes it safely, and checks the result. Works with Claude Desktop and Claude Code.
Test every tool before Claude sees it
Call a tool from the browser and see the raw response, its size in tokens, and which fields to keep so big responses don't flood Claude's context.
Run it remotely for claude.ai and your phone
One command serves the tools over HTTPS, with a built-in OAuth sign-in so claude.ai's "Add custom connector" just works. A Dockerfile is included for hosting.
Use APIs that need you to sign in
OAuth with PKCE for GitHub, Google, Spotify and others. Tokens refresh on their own, even when two Claude apps share one sign-in.
Install ready-made servers from the MCP Registry
Search the official registry and install npm, PyPI or Docker servers, with their keys kept out of config files too.

How it works

  1. You describe an API in project.json: its base URL, how it authenticates, and the tools it offers. The importer can write this for you.
  2. A small generic server, runtime.py, reads that file and turns each tool into an HTTP call, adding the key from the keychain at the last moment.
  3. The installer registers that server with Claude. Adding a tool later is a JSON edit and a restart, never new code.

Where your keys go

  • Into the OS keychain only. Config files, the repo and logs hold a secret:// reference, never the key.
  • Errors report the type of failure, never the request URL, since that can contain a key.
  • A tool argument can't send a request to another host or replace the auth header.
  • The browser UI answers only on 127.0.0.1, only to the person holding its one-time link, and allows no scripts.
  • Remote servers always require a token, and their sign-in tokens are signed, bound to the server, and revoked all at once by rotating the token.

Run it

You need Python 3.13 and uv. Windows, macOS and Linux all work.

git clone https://github.com/ksapp17/mcp-setup-gui
cd mcp-setup-gui
uv sync
uv run gui.py        # opens the browser UI

Then import a spec (try Open-Meteo's weather API, which needs no key), test a tool, and click Install. The README covers the command-line versions, remote hosting, OAuth and the full project.json format.
